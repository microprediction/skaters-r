# Contributing to skaters (R)

This package is a port of the Python reference
([microprediction/skaters](https://github.com/microprediction/skaters)).
One rule governs everything: **the parity gate**. If you know the rule,
every other convention follows.

## The parity gate

`inst/parity/vectors.json` is generated by the Python reference and
pinned to a specific commit (recorded in `PORTING.md`). Every push runs
all scenarios through the R implementation and requires agreement to
1e-6 on roughly 100,000 probe values:

```
Rscript tests/parity.R      # must print PARITY OK
```

Never commit red. The script runs from the repo root, and also inside
`R CMD check` against the installed package; both must pass.

Two further gates live beside it and run the same way:
`tests/robustness.R` (the adversarial streams from the reference repo's
release gate: constant, lattice, monster spike, extreme tick, scale
collapse, vol whiplash, and a long soak that activates the GPD splice)
and `tests/contract.R` (bit-exact determinism across instances, and
checkpoint-resume through saveRDS/readRDS compared with `identical`,
which is why state must stay plain data).

## What "up to date" means here

This port is faithful to skaters *as of the pinned commit*. When the
Python reference gains a numerics feature, nothing breaks here; the
package just ages until someone refreshes. The refresh ritual:

1. In the Python repo: `PYTHONPATH=src python parity/gen_vectors.py`.
2. Copy `parity/vectors.json` here as `inst/parity/vectors.json`.
3. Run the gate. Port whatever new or changed module makes it green.
4. Update the provenance commit in `PORTING.md`.

## Adding a module

Read the Python source and mirror the **operation order** faithfully:
summation order, update order, clamps, floors. That ordering discipline
is what makes 1e-6 achievable. Then register the module's scenarios in
`tests/parity.R`, matching the constructions in the reference repo's
`parity/gen_vectors.py` by name and argument.

Conventions: base R only (jsonlite appears only in tests); skaters are
`function(y, state = NULL)` returning `list(dists = , state = )`;
transforms are `list(forward = , inverse_k = )`; state is plain data,
no environments or closures inside it.

## The R trap that already bit us

R's lazy promises differ from Python in two ways that produced real
bugs during the initial port: closures built in loops capture loop
variables by reference (every candidate silently shared the last
parameter value), and rebinding `f <- wrapper(f, ...)` can make a
wrapper call itself. The fix is mechanical: every factory `force()`s
its arguments and every wrapper `force(base)`s. Keep doing that.

## Releases

r-universe builds continuously from this repository
(`install.packages("skaters", repos = "https://microprediction.r-universe.dev")`).
CRAN releases are occasional, deliberate, and owned by the package
maintainer; `R CMD check --as-cran` must be clean first.
